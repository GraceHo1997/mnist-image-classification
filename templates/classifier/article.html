01 · Objective

Classifying handwritten digits reliably

The objective is to train a convolutional neural network that exceeds 99% validation accuracy on MNIST, then make its predictions accessible through an authenticated web application.

Success criteria

Exceed 99% validation accuracy, retrain the selected architecture on all 60,000 training images, and evaluate it once on the untouched test set.

02 · Dataset and preprocessing

Consistent inputs for training and inference

MNIST contains grayscale images of handwritten digits. Each image is represented by 28 rows and 28 columns. Training values are converted to 32-bit floating point numbers, scaled from 0–255 to 0–1, and reshaped to include one image channel.

03 · Validation approach

Selecting the model without touching the test set

During experimentation, 20% of training observations are reserved with validation_split=0.2. Architecture and training decisions use validation performance; the test set remains untouched until the final architecture is fixed and retrained.

05 · Final architecture

Learning local patterns before classification

The candidate network uses stacked small convolutional filters to detect strokes and curves, pooling to reduce spatial dimensions, dropout to control overfitting, and a softmax output for digits 0 through 9.

08 · Limitations and improvements

Why 100% accuracy may not be realistic

Some handwritten digits are inherently ambiguous. Dataset labeling, limited training variation, and overlap between writing styles constrain generalization. Future work could examine targeted augmentation, calibration, and high-confidence errors.

09 · Why results can change across runs

Neural-network training is stochastic

Repeated training runs of the same architecture can produce slightly different results. Random weight initialization, training-data shuffling, dropout, data augmentation, and nondeterministic GPU operations can send the optimizer along different training paths.

That variation appeared when Models 2 and 3 were trained again. In the recorded model-selection run, Model 2 achieved 99.5083% validation accuracy and Model 3 achieved 99.4750%. In an independent team rerun, Model 2 achieved 99.4667% while Model 3 achieved 99.5833%.

How to interpret the difference

In the recorded selection run, the gap between Models 2 and 3 represented only four of the 12,000 validation images. In the independent rerun, the gap represented about 14 images. These small margins indicate that the two architectures performed very similarly and that their ranking was sensitive to normal training randomness.

Model 2 was kept as the deployed model because it was selected from the original recorded validation results before the test set was examined. It exceeded the 99.5% stretch goal in that run and trained more quickly than Model 3, which required an additional convolutional block and real-time data augmentation. Changing the selected architecture after seeing a later rerun would have changed the original model-selection procedure.

After selection, Model 2 was rebuilt with fresh weights, trained on all 60,000 training images, and evaluated once on the untouched test set. The saved model achieved 99.57% test accuracy and is the model deployed in the Django application.

The rerun does not mean that either result was incorrect. It shows why very small accuracy differences from a single training run should be interpreted cautiously. A stronger comparison would repeat each architecture multiple times and compare average performance and variability, although that would require substantially more computation.
