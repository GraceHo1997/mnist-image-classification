01 · Objective

Classifying handwritten digits reliably

The goal of this project was to develop a convolutional neural network that could classify handwritten MNIST digits with greater than 99% validation accuracy.

Rather than training only one network, we compared multiple CNN architectures. Model-selection decisions were made using validation performance, while the test set was kept separate until the final architecture and training strategy had been fixed.

Project goal

Compare multiple CNN architectures, exceed 99% validation accuracy, select a final architecture without using the test set, retrain it on all 60,000 training images, and evaluate its generalization on the untouched 10,000-image test set.

02 · Dataset and preprocessing

Turning pixels into consistent model inputs

MNIST contains grayscale images of handwritten digits from 0 through 9. Each image contains 28 rows and 28 columns of pixel intensities.

The original pixel values range from 0 to 255. Before training, the images are converted to 32-bit floating-point values and normalized to the 0–1 range. A single channel dimension is then added so each image has the CNN input shape 28 × 28 × 1.

03 · How the CNN reads a digit

Learning local visual patterns

A convolutional neural network does not memorize complete digit images. Instead, its convolutional filters examine small local regions and learn patterns that are useful for distinguishing one digit from another.

Early convolutional layers can respond to simple visual structures such as edges, corners, curves, and short strokes. Deeper layers combine those simpler patterns into more meaningful features that represent the overall structure of a handwritten digit.

Why use small convolutional filters?

Small filters allow the network to focus on local stroke patterns while deeper layers gradually combine those patterns into higher-level representations.

ReLU activation preserves useful positive responses. Max-pooling reduces spatial dimensions while keeping strong activations, which lowers computational cost while preserving important image information.

After the convolutional stages, the remaining feature maps are flattened and passed to dense layers. The final softmax layer produces ten class probabilities, and the digit with the highest probability becomes the model's prediction.

04 · Model development

From a baseline CNN to a deeper regularized network

Three candidate architectures were trained and compared. Each new model tested whether greater depth, stronger regularization, or data augmentation could improve validation performance.

Model 1 · Baseline CNN

Model 1 provided the baseline. It used two convolutional layers followed by pooling and dense classification layers.

The model achieved 98.8583% validation accuracy in the recorded model-selection run. Although this was strong performance, it did not reach the project's required 99% validation threshold.

Model 2 · Deeper CNN with batch normalization and dropout

Model 2 expanded the baseline from two convolutional layers to four, allowing the network to learn more detailed and higher-level visual features.

The convolutional layers used small 3 × 3 filters with same padding so spatial information could be preserved before pooling.

Batch normalization was added after each convolutional layer to stabilize training. Dropout was added after pooling and dense layers to reduce overfitting, and the dense classification layer was increased from 64 to 128 nodes.

Model 3 · Additional depth and data augmentation

Model 3 added a third convolutional block and introduced real-time data augmentation during training.

Small random rotations and translations were applied to training images to simulate natural handwriting variation and encourage the network to recognize digits even when they were slightly shifted or rotated.

This made Model 3 more flexible, but it also increased training complexity and did not improve validation accuracy over Model 2 in the recorded model-selection run.

Preserving enough information

We also examined the flatten-layer dimensions to ensure that repeated convolution and pooling did not shrink the feature representation too aggressively. Model 1 retained 1,600 flattened features, Model 2 retained 3,136, and Model 3 retained 1,152.

05 · Why Model 2 was selected

The best recorded validation result without Model 3's extra complexity

Model Parameters Epochs run Best epoch Validation accuracy
Model 1 121,930 10 7 98.8583%
Model 2 468,778 20 18 99.5083%
Model 3 289,066 14 9 99.4750%

In the recorded model-development run used for architecture selection, Model 2 achieved the highest validation accuracy at 99.5083%. Model 3 achieved 99.4750%, only 0.0333 percentage points lower.

That difference is equivalent to only four images in the 12,000-image validation set, so the two models should be viewed as performing practically similarly rather than as fundamentally different in quality.

Why keep Model 2?

Model 2 had the highest validation accuracy in the recorded selection run and exceeded the 99.5% stretch goal. It also avoided Model 3's additional convolutional block and real-time data augmentation, making it less computationally demanding.

Most importantly, Model 2 was selected before the test set was examined. The test set therefore remained an independent measure of final generalization.

06 · Final training strategy

Retraining the selected architecture on all 60,000 images

Once Model 2 had been selected, the architecture was rebuilt with fresh weights and trained on the complete 60,000-image MNIST training set for 18 epochs.

During the earlier validation experiment, Model 2 initially learned with an Adam learning rate of 0.001. When validation loss stopped improving, ReduceLROnPlateau reduced the learning rate so the optimizer could make progressively smaller weight updates.

Most of the later validation improvements occurred during these lower-learning-rate fine-tuning stages.

Final training used all 60,000 images, so there was no validation set for ReduceLROnPlateau to monitor. The adaptive callback was therefore replaced with a predetermined schedule based on the learning pattern observed during Model 2 development.

Eighteen epochs were used because Model 2 reached its best validation accuracy at epoch 18. Both the training length and learning-rate schedule were therefore determined from validation-stage results before the test set was evaluated.

07 · Final test performance

Strong performance on previously unseen digits

Training accuracy 99.7883%
Test accuracy 99.5700%
Test loss 0.012706
Test error rate 0.43%

On the untouched 10,000-image MNIST test set, the final model correctly classified 9,957 images and misclassified only 43.

The selected Model 2 had achieved 99.5083% validation accuracy, while the final test accuracy was 99.57%. The difference was only 0.0617 percentage points.

What this suggests

The similarity between validation and test performance provides strong evidence that the model generalized well and did not exhibit substantial overfitting.

Test accuracy was also calculated independently by taking the argmax of the ten class probabilities for every test image. This produced the same 99.57% accuracy as model.evaluate(), confirming that the prediction outputs were processed consistently.

08 · Error analysis

What the model still gets wrong

The final model misclassified only 43 of the 10,000 test images. Rather than being completely random, many of the remaining errors were concentrated around digits with similar stroke geometry.

True digit Predicted as Number of errors Possible visual reason
2 7 4 Weak lower horizontal stroke
5 3 4 Faint vertical stroke with dominant curves
9 4 4 Open loop or unusual vertical stroke

These three confusion pairs accounted for 12 of the 43 errors, approximately 27.9% of all misclassifications.

Why digit 6 was particularly challenging

Digit 6 had the lowest class-specific recall. The model correctly classified 950 of the 958 test images labeled as 6, corresponding to a recall of approximately 99.16%.

Its eight errors included examples classified as 0, 1, or 8 twice each, plus isolated predictions as 4 and 5.

Ambiguous handwriting matters

A 6 with an open or faint loop can resemble an incomplete 0, a curved 1, or an 8 with a poorly separated upper loop. Likewise, a 2 with a weak lower stroke can resemble a 7, and a 9 with an open loop can resemble a 4.

MNIST images are only 28 × 28 pixels, so subtle stroke details can be lost. Unusual handwriting styles and occasional ambiguous examples can therefore remain difficult even for a highly accurate model.

Additional augmentation, model ensembles, or more advanced architectures could potentially reduce some of these errors, but achieving 100% accuracy on genuinely unseen handwriting is unlikely because some digits are inherently ambiguous.

09 · Why results can change across runs

Neural-network training is stochastic

Repeated training runs of the same architecture can produce slightly different results. Random weight initialization, training-data shuffling, dropout, data augmentation, and nondeterministic GPU operations can send the optimizer along different training paths.

Setting the Python, NumPy, and TensorFlow random seeds improves reproducibility, but it does not guarantee that every GPU-based training run will produce exactly the same result.

We observed this variation when Models 2 and 3 were trained again. In the recorded model-selection run, Model 2 achieved 99.5083% validation accuracy while Model 3 achieved 99.4750%.

In an independent team rerun, Model 2 achieved 99.4667%, while Model 3 achieved 99.5833%.

Experiment Model 2 Model 3 Higher accuracy
Recorded model-selection run 99.5083% 99.4750% Model 2
Independent team rerun 99.4667% 99.5833% Model 3
How to interpret the difference

In the recorded selection run, the difference between Models 2 and 3 represented only four of the 12,000 validation images. In the independent rerun, the difference represented approximately 14 images.

These narrow margins show that the two architectures performed very similarly and that their ranking was sensitive to normal training randomness.

Model 2 was kept as the deployed model because it was selected from the original recorded validation results before the test set was examined. It exceeded the 99.5% stretch goal in that run and avoided Model 3's additional convolutional block and real-time data augmentation.

Changing the selected architecture after seeing a later rerun would have changed the original model-selection procedure.

After selection, Model 2 was rebuilt with fresh weights, trained on all 60,000 training images, and evaluated once on the untouched test set. The resulting saved model achieved 99.57% test accuracy and is the model deployed in the Django application.

The rerun does not mean that either result was incorrect. Instead, it demonstrates why extremely small accuracy differences from a single training run should be interpreted cautiously.

A stronger comparison would repeat each architecture multiple times and compare average performance and variability, although doing so would require substantially more computation.
